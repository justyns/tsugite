# v0.21

## 0.21.0 (unreleased)

### Features

- An Activity view lists finished session runs, resolved jobs, schedule runs and compactions, filtered by type.
- Schedules can now deliver their result into a session
- Sessions can be marked as needing the user's attention until it is ack'd
- Warn when scheduled sessions fail too many times
- Session tools and `schedule_create` use current chat session by default
- Added support for setting an alias on sessions
- A blocking question or a parked job also marks a session as needing you
- `{{ conversation_id }}` in an agent template is the conversation the turn belongs to.
- Raw session metadata shows the session's own fields, like its alias, display name and model, alongside the metadata block

### Breaking changes

- Remove the concept of `agents:` at the daemon level.  Daemon mode now has default settings for the default agent/workspace.
- Daemon API endpoints no longer have the `/agents/` prefix.
- Remove the session scratchpad, its `@scratchpad` tools and its API endpoints.

### Changes

- Discord DM sessions no longer claim a session alias.
- Relative timestamps older than a month render as local dates, with the year once older than a year.

### Fixes

- Daemon prompts list each session's agent alongside its status.
- Schedules can be created without an `agent` field.
- Job prompts and errors containing `&` render as valid XML in the agent's context block.
- Resumed sessions replay the `<state>` and `<return_value>` of earlier turns.
- ACP and Claude Code sessions warn the model about untrusted attachments, as other providers do.
- A finished background task's result no longer spills into the chat as the user's own message.
- Multi-step agents finish successfully under the daemon and in Jobs.
- A multi-step run's token and cost totals are recorded against its session.
- An agent-created session reads as idle in the sidebar and its chat header, and keeps taking notifications and delivery cards until it is marked complete.
- A message from another session, a job or a schedule is badged with its sender and links back to it, and the answer says where it went.
- A session-completion wake-up folds into a panel instead of rendering as raw XML in the person's own message.
- A schedule's delivery card in the chat shows the schedule that sent it.
